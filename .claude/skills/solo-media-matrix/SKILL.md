# 自媒体矩阵管理器 / SoloMedia Matrix V2.0

> 一人公司自媒体增长与变现作战台——输入你的领域、时间、内容，输出可直接执行的一周作战计划。

它不是泛泛讲自媒体运营，而是把一个人的**有限时间**转成**一周可执行计划**：平台取舍 → 选题评分 → 一鱼多吃 → 7天排期 → 数据复盘 → 变现动作。

---

## 触发条件

当用户提及以下任一关键词或场景时，立即激活本 Skill：

### 触发关键词
- **账号规划类**：自媒体、矩阵、多平台、账号定位、平台选择、冷启动、做哪些平台
- **内容策划类**：选题、选题库、热点、爆款、内容日历、排期、发什么
- **内容生产类**：一鱼多吃、多平台适配、内容拆解、脚本、标题改写
- **数据复盘类**：数据分析、数据复盘、播放量、完播率、互动率、涨粉诊断
- **变现规划类**：变现、知识付费、带货、私域引流、商单报价、产品矩阵
- **作战计划类**：周计划、作战计划、本周计划、内容规划、运营方案

### 触发场景
- "我想做自媒体，不知道选哪些平台"
- "我每周能投入10小时，帮我规划一下内容策略"
- "我有一篇深度长文，帮我拆成多平台版本"
- "帮我生成本周自媒体作战计划"
- "我这个月各平台数据怎么样，哪个最该加码"
- "我有5000粉丝，怎么变现"
- "我的账号是不是被限流了"

## 核心工作流

当用户提出宽泛需求时，按以下顺序执行：

1. **诊断** → 识别领域、offer、目标客户、每周可投入时间、现有平台、受众规模和变现目标
2. **选平台** → 推荐 1-2 个主平台、1-2 个辅助平台，明确暂缓哪些平台
3. **产内容** → 将核心选题或长内容拆解为各平台适配版本
4. **排日程** → 构建 7 天内容日历，适配每周可用时间
5. **看数据** → 如有数据（CSV/手动输入），跨平台对比，明确加码方向
6. **做变现** → 推荐近期转化动作和长期产品路径
7. **联其它** → 仅在需要时建议同系列其他 Skill

帮一人公司做"做哪些平台、怎么定位"的战略决策。

### 平台推荐引擎

| 领域 | 主平台 | 辅助平台 | 核心逻辑 |
|------|-------|---------|---------|
| 编程技术 | B站、知乎 | 公众号、小红书、视频号 | 技术内容需要代码细节和搜索沉淀 |
| 知识付费 | B站、公众号 | 知乎、视频号 | 长内容信任 + 私域承接 |
| 职场效率 | 小红书、知乎 | 公众号、视频号 | 方法论适合收藏和搜索流量 |
| 美妆护肤 | 小红书、抖音 | 视频号、B站 | 视觉化内容强展示 |
| 本地生活 | 抖音、小红书 | 视频号、微博 | 即时推荐 + 种草交易链 |
| 其他/通用 | 按领域特征推荐 | 按时间预算分配 | — |

**一人公司特殊规则**：

- ⚠️ 每周 > 12 小时 → 最多 4 个平台

```
  3. 办公工具到底怎么选              热度4  潜力5  难度2
```

### 选题评分公式（V2.0 修正版）

```
score = 搜索热度 × 互动潜力 × (6 - 创作难度) / 125 × 100

评分等级：
  ≥ 80 分 → 🟢 优先创作
  60-79 分 → 🟡 本周备选
  40-59 分 → 🔵 放入题库
  < 40 分 → ⚪ 暂不投入
```

**v1.x 旧公式**：`热度 × 潜力 ÷ 难度`（差距不够明显）
**v2.0 新公式**：引入 `(6 - 难度)` 作为难度加成系数，低难度高潜力选题得分显著更高，更符合一人公司"优先做低 hanging fruit"的策略。

**输出**：7 天排期表

## 模块四：数据复盘看板（Analytics Board）

解决数据分散、无从下手的痛点。

### 数据导入（不依赖 API）

**输入**：标准 CSV 格式（用户从各平台后台手动导出后整理）

**CSV 模板**：
```csv
日期,平台,内容标题,播放量,点赞数,评论数,收藏数,分享数,粉丝增长,完播率
2026-05-20,B站,Python自动化办公教程,45000,2800,450,1200,350,320,0.55
2026-05-20,知乎,Python自动化办公解析,12000,650,180,420,95,85,0.72
2026-05-20,小红书,Python办公攻略,3000,380,95,180,28,28,0.45
```

**衍生指标**：互动率 = (点赞+评论+收藏+分享) ÷ 播放量；涨粉率 = 粉丝增长 ÷ 播放量

### 跨平台对比分析

**判断逻辑**：
- 互动率 ≥ 平台平均 × 1.5 或 完播率 ≥ 平台平均 × 1.2 → 🟢 **加码**
- 互动率 < 平台平均 × 0.7 或 完播率 < 平台平均 × 0.7 → 🔴 **优化/降频**
- 其他情况 → 🟡 **保持测试**

**输出示例**：
```
📊 跨平台对比结论：B站表现最佳
| 平台 | 播放量 | 互动率 | 完播率 | 涨粉 | 判断 |
|------|:-----:|:-----:|:-----:|:---:|:----:|
| B站  | 45000 | 10.7% | 55%   | 320 | 🟢 加码 |
| 知乎  | 12000 | 11.3% | 72%   | 85  | 🟢 加码 |
| 小红书 | 3000  | 21.9% | 45%   | 28  | 🟢 保持 |

💡 洞察：
- 最该加码：小红书（互动率21.9%，远超平均）
- 下周只做一个变量实验，不要同时改太多
```

## 模块五：变现路径规划器（Monetization Planner）

解决"有粉丝但不知道怎么赚钱"的痛点。

### 变现阶段自动判断

**输入**：各平台粉丝总数

**输出**：当前阶段 + 本周验证动作

| 粉丝总量 | 阶段 | 本周动作 |
|---------|------|---------|
| < 1000 | 验证期 | 用免费资料包换取私信/社群线索，验证痛点和表达 |
| 1000-10000 | 小产品期 | 上线 9.9-99元 模板/小册，测试付费意愿 |
| > 10000 | 产品矩阵期 | 搭建低价小产品 + 中价训练营 + 高价咨询/陪跑 |

### 分层变现模型

```
引流层（免费）
  └── 领域资料包/检查清单 → 私域引流
      ↓
低价层（9.9-99元）
  └── 模板/小册/工具包 → 验证需求
      ↓
中价层（199-499元）
  └── 训练营/系统课 → 规模化交付
      ↓
高价层（1000元+）
  └── 1对1咨询/陪跑/企业服务 → 利润和案例
```

## 模块七：一键周作战计划（新增 · V2.0）

**这是 V2.0 的核心升级**——将以上所有模块封装为一次调用，输入你的基本信息，输出完整的周作战计划。

### 使用方式

```python
plan = OPCWeeklyOperator.generate_weekly_plan(
    profile=FounderProfile(...),      # 你的个人信息
    core_content=CoreContent(...),     # 核心选题
    metrics_csv="可选CSV数据"          # 如有历史数据
)
```

### 命令行快速体验

```bash
# 默认运行（Python 自动化办公博主示例）

# 带示例数据复盘
python scripts/main.py --with-metrics

# JSON 格式输出（供程序调用）
python scripts/main.py --json
```

### 输出结构

一次 `generate_weekly_plan()` 调用输出以下全部内容：

```
1. 经营判断          → 主平台/辅助平台/暂停平台 + 判断依据
2. 一鱼多吃拆解      → 7个平台适配版本（标题/Hook/交付物/耗时/目标）
3. 7天排期           → 周一到周日的每日任务表
4. 选题候选排序       → 按评分从高到低排列
5. 数据复盘          → 跨平台对比 + 加码/降频判断
6. 变现动作          → 当前阶段 + 产品阶梯建议
7. 今日动作          → 3条立即执行的任务
8. 不做清单          → 3条明确不要做的事
```

## 操作规则

- 计划必须约束在用户的每周可用时间内。超负荷时优先减少平台数量
- 优先用一篇核心内容跨平台复用，不要为每个平台单独生产
- 一人公司推荐最多 3-4 个活跃平台
- 明确区分**主平台**、**辅助平台**、**暂停平台**，并给出原因
- 输出必须可执行：具体的标题、Hook、脚本、日期、指标和阈值
- 平台规则和变现门槛为参考值，重大决策前须以各平台官方后台为准

## 反模式与常见误区

**⚠️ 以下是使用本 Skill 时最常见的高风险行为，请务必避免：**

| ❌ 错误用法 | ✅ 正确用法 | 为什么 |
|-----------|-----------|--------|
| 一上来就做全平台日更 | 先确定 2-3 个核心平台，做深做透 | 一人精力有限，质量比数量重要 |
| 每个平台都从头创作 | 用"一鱼多吃"策略，一篇母内容拆多篇 | 一人公司单篇创作成本已经很高 |
| 同时测试多个变量 | 每次只改变一个变量（标题或封面或时长） | 多变量同时测试无法归因 |
| 只看播放量/粉丝数 | 关注互动率、完播率、收藏率 | 互动数据更能反映内容质量 |
| 有几百粉就想接商单 | 先验证内容方向和变现模型 | 粉丝少时优先做产品和信任 |
| 忽略平台规则变化 | 定期做账号健康体检 | 一次违规可能毁掉积累 |

### 高频容易踩的坑

1. **"我做内容就只靠平台自然流量"** — 所有平台自然流量都在下降，建议从第一天就积累私域
2. **"选最多的平台就能覆盖最多人"** — 一人公司应选"内容形态最适合你"的平台而非"用户最多"的平台
3. **"数据不好就换方向"** — 至少连续发 10-15 条同方向内容再做判断，单条数据波动正常

## 安全边界与使用约束

**本 Skill 的能力边界（必须遵守）：**

1. **这不是自媒体代运营**：本 Skill 提供的是运营决策参考，不替代实际内容创作和发布。
2. **不实时追踪热点**：除非用户主动提供或要求搜索，本 Skill 不声称了解当前实时热点。
3. **平台规则为参考值**：各平台算法、规则、变现门槛变化快，商业决策前请以官方后台为准。
4. **数据来源限制**：数据分析仅基于用户主动提供的 CSV 或手动输入数据，不调用任何平台 API。
5. **变现建议非承诺**：变现模型基于行业经验，实际收入受多种因素影响，不作任何承诺。

**AI 使用时的安全规则：**
- **Always** 在给出平台推荐时附上判断依据，而非独断式结论
- **Always** 在涉及变现/投放/签约决策时，增加"请以官方后台核实"提示
- **Never** 声称能预测"这条内容一定爆款"或"这个账号一定能做起来"
- **Never** 建议用户违反平台规则（如"买粉""刷量""搬运"）
